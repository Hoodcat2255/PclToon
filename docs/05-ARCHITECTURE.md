## 3. 컴포넌트 구조

### 컴포넌트 트리

```
+layout.svelte              (루트 레이아웃)
  └── +page.svelte          (메인 페이지, 상태 머신)
       ├── Header           (항상 렌더링)
       │   └── ThemeToggle
       ├── LinkInput        (currentView === 'input' 일 때)
       ├── EpisodeList      (currentView === 'list' 일 때)
       └── ImageViewer      (currentView === 'viewer' 일 때)
```

### 각 컴포넌트 상세

#### `+layout.svelte` (루트 레이아웃)
- **역할**: 전역 CSS 임포트, 테마 스토어 초기화, 테마 CSS 클래스 적용
- **props**: `children` (Svelte 5 snippet)
- **로직**: `onMount`에서 `theme.init()` 호출. `$theme` 값(`'dark'` 또는 `''`)을 루트 `<div>`의 class로 적용
- **Svelte 5 문법**: `$props()`, `{@render children()}`

#### `+page.svelte` (메인 페이지)
- **역할**: 앱의 핵심 로직 담당. 상태 머신으로 3개 뷰를 전환
- **상태 변수** (모두 `$state()` rune 사용):
  - `currentView`: `'input'` | `'list'` | `'viewer'` -- 현재 활성 뷰
  - `code`: pCloud 공유 코드 문자열
  - `rootData`: `fetchPublicLink()` API 응답 원본
  - `currentFolder`: 현재 선택된 폴더 객체
  - `folders`: 현재 레벨의 폴더 배열 (필터링 + 정렬 완료)
  - `images`: 현재 레벨의 이미지 파일 배열 (필터링 + 정렬 완료)
  - `breadcrumb`: 탐색 경로 배열. 각 항목은 `{ name, data }` (루트) 또는 `{ name, folder }` (하위)
- **핵심 함수**:
  - `handleLinkSubmit(url)`: 링크 제출 처리. `extractCode()` → `fetchPublicLink()` → 콘텐츠 분류 → 뷰 전환
  - `handleFolderSelect(folder)`: 폴더 선택 처리. 콘텐츠 분류 → breadcrumb 추가 → 뷰 전환
  - `handleBack()`: 뒤로가기. breadcrumb에서 이전 항목 복원 또는 초기 상태로 리셋
  - `isImageFile(filename)`: 파일 확장자로 이미지 여부 판별 (jpg, jpeg, png, gif, webp, bmp)
  - `getCurrentTitle()`: breadcrumb 마지막 항목의 name 반환, 없으면 `'PclToon'`
- **참고**: `isImageFile()`과 콘텐츠 분류 로직이 `pcloud.js`의 유틸리티 함수(`isImageFile`, `processContents`)와 중복 구현되어 있다. `+page.svelte`에서는 `pcloud.js`의 유틸리티를 사용하지 않고 인라인으로 직접 구현한다.

#### `Header.svelte`
- **역할**: 고정(sticky) 상단 헤더. 뒤로가기 버튼, 제목, 테마 토글 포함
- **props**: `title` (기본값: `'pCloud Comics'`), `showBack` (기본값: `false`), `onBack` (콜백)
- **스타일**: `sticky top-0 z-50`, 반투명 배경 + `backdrop-blur-sm`

#### `LinkInput.svelte`
- **역할**: pCloud 공유 링크 입력 폼
- **props**: `onSubmit` (async 콜백)
- **상태**: `inputValue`, `isLoading`, `error` (모두 `$state()`)
- **동작**: 폼 제출 시 `onSubmit(inputValue.trim())` 호출. 로딩 상태와 에러 메시지 관리

#### `EpisodeList.svelte`
- **역할**: 폴더 목록을 버튼 리스트로 표시
- **props**: `folders` (배열, 기본값: `[]`), `onSelect` (콜백)
- **동작**: 폴더가 없으면 "No folders found" 메시지 표시. 각 폴더를 클릭하면 `onSelect(folder)` 호출
- **참고**: `{#each}` 블록에 key가 지정되지 않았다

#### `ImageViewer.svelte`
- **역할**: 이미지를 세로 스크롤 형태로 표시하는 뷰어
- **props**: `images` (배열, 기본값: `[]`), `code` (pCloud 공유 코드), `folderId` (폴더 ID)
- **상태**: `imageUrls` (실제 다운로드 URL 배열), `loadedCount` (로딩 완료 카운트), `containerRef` (DOM 참조)
- **동작**:
  1. `onMount`에서 `localStorage`의 저장된 읽기 위치(bookmark) 확인
  2. 모든 이미지에 대해 `Promise.all`로 `getImageUrl()` 병렬 호출하여 실제 URL 획득
  3. 실패한 이미지는 `null` 반환 후 필터링으로 제외
  4. 저장된 위치가 있으면 `setTimeout(100ms)` 후 해당 스크롤 위치로 복원
  5. 로딩 진행 상태를 우하단 오버레이로 표시 (`loadedCount / total`)
  6. 페이지 이탈 시(`beforeunload`) 및 컴포넌트 파괴 시 현재 스크롤 위치를 localStorage에 저장
- **이미지 로딩**: 브라우저 네이티브 `loading="lazy"` 속성 사용
- **최대 너비**: `max-w-3xl` (Tailwind, 48rem = 768px)
- **배경**: 이미지 뷰어 영역은 항상 검은색 배경 (`bg-black`)

#### `ThemeToggle.svelte`
- **역할**: 다크/라이트 모드 전환 버튼
- **동작**: `theme.toggle()` 호출. 다크 모드일 때 태양 아이콘(라이트 전환 의미), 라이트 모드일 때 달 아이콘(다크 전환 의미) 표시
- **아이콘**: 인라인 SVG 사용

## 4. 데이터 흐름

### 전체 흐름

```
사용자 입력 (pCloud URL)
    │
    ▼
extractCode(url)                   URL에서 공유 코드 추출
    │
    ▼
fetchPublicLink(code)              pCloud API 호출: showpublink
    │                              GET https://api.pcloud.com/showpublink?code={code}
    │                              → 폴더 구조 + 메타데이터 반환
    ▼
콘텐츠 분류                         metadata.contents에서 폴더/이미지 분리
    │                              isImageFile()로 이미지 필터링
    │                              localeCompare()로 자연 정렬
    │
    ├─ 이미지만 존재 ──────────────→ ImageViewer (viewer 뷰)
    │
    └─ 폴더 존재 ──────────────────→ EpisodeList (list 뷰)
                                        │
                                        ▼ (폴더 선택)
                                   콘텐츠 분류 (재귀)
                                        │
                                        ├─ 이미지 있음 → ImageViewer
                                        └─ 폴더만 있음 → EpisodeList (중첩 탐색)
```

### pCloud API 호출 상세

#### 1단계: 공유 링크 메타데이터 조회
- **엔드포인트**: `GET https://api.pcloud.com/showpublink?code={code}`
- **호출 위치**: `pcloud.js` > `fetchPublicLink()`
- **응답 구조**: `{ metadata: { name, contents: [{ name, isfolder, fileid, contents?, ... }] } }`
- **에러 처리**: `data.error` 존재 시 `throw new Error(data.error)`

#### 2단계: 개별 이미지 다운로드 URL 획득
- **엔드포인트**: `GET https://api.pcloud.com/getpublinkdownload?code={code}&fileid={fileid}`
- **호출 위치**: `pcloud.js` > `getImageUrl()`
- **옵션**: `referrerPolicy: 'no-referrer'`
- **응답 구조**: `{ hosts: ["hostname"], path: "/path/to/file" }`
- **URL 조립**: `https://{hosts[0]}{path}`
- **호출 패턴**: `ImageViewer.svelte`의 `onMount`에서 `Promise.all`로 모든 이미지에 대해 병렬 호출

### URL 파싱 (`extractCode`)

3가지 정규식 패턴을 순서대로 시도:

1. `code=([a-zA-Z0-9]+)` -- 쿼리 파라미터에서 추출
2. `publink/show\?code=([a-zA-Z0-9]+)` -- publink 경로에서 추출
3. `/([a-zA-Z0-9]+)$` -- URL 마지막 경로 세그먼트
4. 모든 패턴 불일치 시 입력값을 그대로 코드로 사용

### 정렬 방식

모든 콘텐츠(폴더, 이미지)는 `localeCompare`의 `{ numeric: true, sensitivity: 'base' }` 옵션으로 자연 정렬된다. 이는 "Chapter 2"가 "Chapter 10"보다 앞에 오도록 보장한다.

## 5. 상태 관리

### 앱 레벨 상태 (반응형, 메모리)

`+page.svelte`에서 Svelte 5의 `$state()` rune으로 관리하는 상태:

| 상태 변수 | 타입 | 초기값 | 용도 |
|-----------|------|--------|------|
| `currentView` | `string` | `'input'` | 현재 활성 뷰 (`'input'`/`'list'`/`'viewer'`) |
| `code` | `string` | `''` | pCloud 공유 코드 |
| `rootData` | `object\|null` | `null` | API 응답 원본 데이터 |
| `currentFolder` | `object\|null` | `null` | 현재 선택된 폴더 객체 |
| `folders` | `array` | `[]` | 현재 레벨의 폴더 목록 |
| `images` | `array` | `[]` | 현재 레벨의 이미지 목록 |
| `breadcrumb` | `array` | `[]` | 탐색 경로 (뒤로가기용) |

### 상태 머신 (뷰 전환)

```
                handleLinkSubmit()
    ┌─────────────────────────────────────────┐
    │                                         │
    │   ┌───────┐   이미지만   ┌──────────┐   │
    │   │ input ├─────────────→│  viewer  │   │
    │   └───┬───┘              └────┬─────┘   │
    │       │                       │  ▲      │
    │       │ 폴더 있음    handleBack│  │      │
    │       │                       │  │ 이미지 있음
    │       ▼                       ▼  │      │
    │   ┌───────┐  handleFolderSelect  │      │
    │   │ list  ├──────────────────────┘      │
    │   └───┬───┘                             │
    │       │                                 │
    │       │ handleBack (breadcrumb 비어있음)  │
    │       └─────────────────────────────────┘
    │                    │
    └────────────────────┘
         handleBack (최상위)
```

**전환 규칙:**
- `input` → `viewer`: 루트에 이미지만 있고 폴더가 없을 때
- `input` → `list`: 루트에 폴더가 있을 때
- `list` → `viewer`: 선택한 폴더에 이미지가 있을 때
- `list` → `list`: 선택한 폴더에 하위 폴더만 있을 때 (폴더 중첩 탐색)
- `viewer` → `list`: 뒤로가기 + 현재 레벨에 폴더가 남아있을 때
- `viewer`/`list` → `input`: 뒤로가기 + breadcrumb이 비어있을 때 (전체 상태 리셋)

### 영속 상태 (localStorage)

| 키 | 형식 | 관리 주체 | 용도 |
|----|------|-----------|------|
| `theme` | `'dark'` 또는 `''` | `theme.js` 스토어 | 테마 설정 |
| `bookmark_{code}_{folderId}` | 스크롤 Y 좌표 (문자열) | `ImageViewer.svelte` | 읽기 위치 저장 |

### 테마 스토어 (`theme.js`)

Svelte의 `writable` 스토어를 커스텀 팩토리 함수로 감싼 구조:

- **`init()`**: 브라우저 환경에서 호출. localStorage에 저장된 값 우선, 없으면 `prefers-color-scheme: dark` 미디어 쿼리 결과로 결정
- **`toggle()`**: `'dark'` ↔ `''` 전환 + localStorage 저장
- **`set(value)`**: 지정 값으로 설정 + localStorage 저장
- **값 체계**: `'dark'` (다크 모드) 또는 `''` (빈 문자열, 라이트 모드)

테마 값은 `+layout.svelte`의 루트 `<div>`에 class로 적용된다. `'dark'` 클래스가 적용되면 `app.css`의 `.dark` 선택자가 CSS 커스텀 프로퍼티를 오버라이드하고, 각 컴포넌트의 `dark:` Tailwind 변형이 활성화된다.

## 6. 외부 의존성

### 런타임 의존성

| 의존성 | 유형 | 용도 |
|--------|------|------|
| pCloud Public API (`api.pcloud.com`) | REST API | 공유 링크 메타데이터 조회 + 이미지 다운로드 URL 획득 |

- **인증 없음**: 공개 링크(public link)만 사용하므로 API 키나 인증 토큰이 불필요
- **CORS**: pCloud API가 CORS를 허용하여 브라우저에서 직접 호출 가능
- **referrerPolicy**: 이미지 다운로드 URL 획득 시 `no-referrer` 정책 적용

### 빌드 타임 의존성

모든 npm 패키지가 `devDependencies`에 위치:

| 패키지 | 용도 |
|--------|------|
| `@sveltejs/kit` | SvelteKit 프레임워크 |
| `@sveltejs/adapter-static` | 정적 사이트 빌드 어댑터 |
| `@sveltejs/adapter-auto` | 자동 어댑터 (사용되지 않음, adapter-static으로 대체됨) |
| `@sveltejs/vite-plugin-svelte` | Vite용 Svelte 플러그인 |
| `svelte` | Svelte 5 컴파일러 |
| `tailwindcss` | Tailwind CSS |
| `@tailwindcss/vite` | Tailwind Vite 플러그인 |
| `vite` | 빌드 도구 |

### 서버/데이터베이스 의존성

없음. 완전한 클라이언트 사이드 애플리케이션이다.

## 7. 빌드 및 배포

### 빌드 설정

#### `svelte.config.js`
- **어댑터**: `@sveltejs/adapter-static`
  - `pages: 'build'` -- 빌드 출력 디렉토리
  - `assets: 'build'` -- 정적 에셋 출력 디렉토리
  - `fallback: 'index.html'` -- SPA 폴백 (클라이언트 사이드 라우팅 지원)
  - `precompress: false` -- 사전 압축 비활성화
  - `strict: true` -- 엄격 모드
- **base path**: 프로덕션(`NODE_ENV === 'production'`)에서 `/PclToon`, 개발 환경에서 빈 문자열

#### `vite.config.js`
- **플러그인**: `tailwindcss()` + `sveltekit()` (이 순서로 등록)

#### `+layout.js` (SPA 모드)
- `export const prerender = true` -- 사전 렌더링 활성화 (정적 HTML 생성)
- `export const ssr = false` -- 서버 사이드 렌더링 비활성화 (클라이언트 전용)

### 배포 파이프라인 (GitHub Actions)

`.github/workflows/deploy.yml`에 정의된 2단계 워크플로우:

```
main 브랜치 push / 수동 트리거
         │
         ▼
    ┌─────────┐
    │  build   │  ubuntu-latest, Node 20
    │          │  npm ci → npm run build (NODE_ENV=production)
    │          │  → build/ 디렉토리를 Pages artifact로 업로드
    └────┬────┘
         │
         ▼
    ┌─────────┐
    │  deploy  │  GitHub Pages 배포
    │          │  actions/deploy-pages@v4
    └─────────┘
```

**트리거 조건:**
- `main` 브랜치에 push
- `workflow_dispatch` (수동 실행)

**권한:**
- `contents: read` -- 저장소 코드 읽기
- `pages: write` -- GitHub Pages 배포
- `id-token: write` -- OIDC 토큰 (Pages 배포에 필요)

**동시성 제어:**
- `group: 'pages'` -- 동일 그룹 내 동시 실행 방지
- `cancel-in-progress: false` -- 진행 중인 배포를 취소하지 않음

## 8. 주요 설계 결정

### 1. 완전한 클라이언트 사이드 SPA

서버 없이 정적 파일만으로 동작한다. `ssr: false`와 `adapter-static`의 `fallback: 'index.html'` 조합으로 모든 라우팅을 클라이언트에서 처리한다. 이를 통해 GitHub Pages 같은 정적 호스팅에 별도 서버 설정 없이 배포할 수 있다.

### 2. 단일 페이지 상태 머신 방식의 뷰 전환

SvelteKit의 파일 기반 라우팅 대신, `+page.svelte` 하나에서 `currentView` 변수로 3개 뷰(`input`/`list`/`viewer`)를 조건부 렌더링한다. URL 기반 라우팅을 사용하지 않으며, 뒤로가기는 자체 `breadcrumb` 배열로 구현한다. 이 방식은 pCloud 공유 코드와 폴더 계층 상태를 컴포넌트 내부에서 단순하게 관리할 수 있게 한다.

### 3. pCloud API 직접 호출 (프록시 없음)

브라우저에서 `api.pcloud.com`을 직접 호출한다. pCloud Public API가 CORS를 허용하고, 공개 링크에는 인증이 불필요하기 때문에 프록시 서버가 필요 없다. 이미지 다운로드 URL 획득 시 `referrerPolicy: 'no-referrer'`를 설정하여 레퍼러 기반 차단을 회피한다.

### 4. 이미지 URL의 2단계 획득

이미지를 직접 로드할 수 없고, 먼저 `getpublinkdownload` API로 임시 다운로드 URL을 획득해야 한다. `ImageViewer`는 `onMount`에서 `Promise.all`로 모든 이미지의 URL을 병렬로 가져온 뒤 한번에 렌더링한다. URL 획득에 실패한 이미지는 조용히 제외된다 (`catch` → `null` → `filter(Boolean)`).

### 5. CSS 커스텀 프로퍼티 기반 테마 시스템

`app.css`에서 `:root`와 `.dark` 선택자로 CSS 변수(`--bg-primary`, `--bg-secondary`, `--text-primary`, `--text-secondary`)를 정의한다. 동시에 각 컴포넌트에서는 Tailwind의 `dark:` 변형을 사용한다. 이 두 방식이 공존하며, 테마 전환 시 `body`에 0.3초 트랜지션이 적용된다.

### 6. localStorage 기반 읽기 위치 저장

`bookmark_{code}_{folderId}` 키로 각 에피소드별 스크롤 Y 좌표를 저장한다. 페이지 이탈(`beforeunload` 이벤트) 시와 컴포넌트 파괴 시 자동 저장되며, 해당 에피소드 재진입 시 저장된 위치로 스크롤을 복원한다. 복원 시 100ms 지연을 두어 이미지 렌더링 후 스크롤이 적용되도록 한다.

### 7. 브라우저 네이티브 지연 로딩

커스텀 Intersection Observer 대신 HTML `<img>` 태그의 `loading="lazy"` 속성을 사용한다. 별도의 라이브러리 없이 브라우저 기본 기능만으로 이미지 지연 로딩을 구현한다.

### 8. 프로덕션 환경 base path 분기

`svelte.config.js`에서 `NODE_ENV`에 따라 base path를 분기한다. 프로덕션에서는 `/PclToon` (GitHub Pages의 저장소 경로), 개발 환경에서는 빈 문자열이다. 이로 인해 GitHub Pages의 `https://{user}.github.io/PclToon/` 경로에서 정상 동작한다.

### 9. 유틸리티 함수 중복 구현

`pcloud.js`에 `isImageFile()`, `processContents()`, `naturalSort()` 유틸리티가 정의되어 있으나, `+page.svelte`에서는 이를 임포트하지 않고 동일 로직을 인라인으로 재구현한다. `extractCode()`와 `fetchPublicLink()`만 `pcloud.js`에서 임포트한다.

### 10. 제로 런타임 의존성

`package.json`에 `dependencies` 필드가 없고 모든 패키지가 `devDependencies`에 위치한다. 빌드 결과물은 순수한 정적 파일(HTML, CSS, JS)이며, 런타임에 외부 CDN이나 npm 패키지에 의존하지 않는다.
