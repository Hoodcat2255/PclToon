# 09. Security Plan

## 1. 보안 개요

PclToon은 순수 클라이언트 사이드 SPA로, 백엔드 서버와 데이터베이스 없이 GitHub Pages에 정적 파일로 호스팅된다. pCloud Public API(인증 불필요)만 호출하며, 사용자 계정/인증 시스템이 존재하지 않는다.

**핵심 보안 특성:**

| 항목 | 상태 |
|------|------|
| 백엔드 서버 | 없음 -- 모든 로직이 클라이언트 측에서 실행 |
| 데이터베이스 | 없음 |
| 사용자 인증/계정 | 없음 -- 로그인, 세션 관리 부재 |
| API 키/시크릿 | 없음 -- 민감 자격 증명을 저장하거나 처리하지 않음 |
| 외부 API 의존 | pCloud 공개 API만 사용 (인증 헤더 없이 접근) |
| 공격 표면 | 최소 -- 순수 읽기 전용 뷰어 애플리케이션 |

**공격 표면(Attack Surface)**: 클라이언트 브라우저 환경, pCloud API 통신, 사용자 입력(URL), localStorage로 제한된다.

## 2. 인증/인가

**현재 상태: 해당 없음 (N/A)**

- 사용자 계정 시스템이 존재하지 않음
- 로그인, 회원가입, 비밀번호 관리 기능 없음

- `fetch()` 호출 시 `Authorization` 헤더 없음
- 앱 자체에 권한 분리나 역할 기반 접근 제어(RBAC) 없음

## 3. 입력 검증

### 3.1 URL 입력 (`LinkInput.svelte`)

사용자 입력 진입점은 단 하나: `LinkInput.svelte`의 pCloud URL 입력 필드이다.

**구현된 사항:**
- `inputValue.trim()`으로 공백 제거 후 `onSubmit` 콜백으로 전달
- 빈 문자열 입력 방지: `if (!inputValue.trim()) return;`
- 에러 발생 시 `err.message`를 Svelte 텍스트 보간(`{error}`)으로 화면에 표시 -- 자동 이스케이프됨

**미구현 사항:**
- 입력 필드에 `maxlength` 속성 없음
- URL 형식 유효성 사전 검증 없음

### 3.2 코드 추출 (`pcloud.js > extractCode`)

정규식 패턴 3개를 순차 매칭하여 share code를 추출한다:

```javascript
const patterns = [
    /code=([a-zA-Z0-9]+)/,              // URL 쿼리 파라미터
    /publink\/show\?code=([a-zA-Z0-9]+)/, // pCloud 공개 링크 형식
    /\/([a-zA-Z0-9]+)$/                  // 경로 끝 코드
];
```

- 캡처 그룹 `[a-zA-Z0-9]+`로 영숫자만 허용 -- 추출된 코드에 특수 문자가 포함될 수 없음
- **매칭 실패 시**: 입력값을 그대로 반환 (`return url;`) -- 원본 입력값 전체가 code로 사용됨
- 추출된 code는 URL 쿼리 파라미터에 직접 삽입:
  - `https://api.pcloud.com/showpublink?code=${code}`
  - `https://api.pcloud.com/getpublinkdownload?code=${code}&fileid=${fileid}`

### 3.3 API 응답 처리

- `data.error` 존재 시 `throw new Error(data.error)` -- pCloud API 에러 메시지를 그대로 Error 객체에 전달
- 에러 메시지가 UI까지 전달되어 `err.message`로 표시됨
- 응답 구조의 타입 검증이나 스키마 검증은 수행하지 않음
- `data.hosts[0]`, `data.path`, `data.metadata?.contents` 등에 대한 존재/타입 검증 없이 직접 접근

### 3.4 파일 확장자 필터링

```javascript
const IMAGE_EXTENSIONS = ['jpg', 'jpeg', 'png', 'gif', 'webp', 'bmp'];
```

- `isImageFile()` 함수가 화이트리스트 방식으로 이미지 파일만 필터링
- 파일명에서 `.split('.').pop()?.toLowerCase()`로 확장자 추출

### 3.5 XSS 방지 현황

- `innerHTML`, `dangerouslySetInnerHTML`, `eval()` 사용 없음
- `{@html}` 디렉티브 사용 없음 -- 모든 동적 콘텐츠가 Svelte 텍스트 보간(`{variable}`)으로 렌더링되어 자동 이스케이프
- DOM 직접 조작(innerHTML, document.write 등) 없음
- pCloud API 응답의 `name` 필드가 UI에 표시되지만, Svelte 텍스트 보간을 통해 자동 이스케이프됨
- 외부 JavaScript 라이브러리를 런타임에 동적 로딩하지 않음

## 4. 데이터 보호

### 4.1 localStorage 사용 현황

| 키 형식 | 값 | 용도 | 파일 |
|---------|-----|------|------|
| `theme` | `"dark"` 또는 `""` | 다크모드 설정 | `src/lib/stores/theme.js` |
| `bookmark_{code}_{folderId}` | 스크롤 Y 좌표 (정수 문자열) | 읽기 위치 북마크 | `src/lib/components/ImageViewer.svelte` |

**보안 평가:**
- 저장 데이터에 민감 정보(비밀번호, 토큰, 개인정보) 없음
- pCloud share code가 localStorage 키에 포함되지만, 이는 이미 공개 링크의 일부로 비밀 정보가 아님
- `typeof window !== 'undefined'` 가드로 SSR 안전성 확보 (`theme.js`)
- `parseInt(savedPosition, 10)`으로 스크롤 위치를 파싱하여 비정상 값은 NaN으로 처리됨
- 세션 토큰, 자격 증명, 개인정보는 저장되지 않음

### 4.2 미사용 저장소

- Cookie: 사용하지 않음
- sessionStorage: 사용하지 않음
- IndexedDB: 사용하지 않음

### 4.3 메모리 내 데이터

- 이미지 URL(`imageUrls`)은 컴포넌트 `$state`로만 유지, 별도 캐싱이나 영구 저장 없음
- pCloud API 응답 데이터는 처리 후 참조만 유지

## 5. 네트워크 보안

### 5.1 API 호출

PclToon이 호출하는 pCloud API 엔드포인트:

| 엔드포인트 | 용도 | 메서드 |
|---|---|---|
| `https://api.pcloud.com/showpublink?code={code}` | 공개 링크 메타데이터 조회 | GET (fetch) |
| `https://api.pcloud.com/getpublinkdownload?code={code}&fileid={fileid}` | 이미지 다운로드 URL 획득 | GET (fetch) |

- 모든 API 호출이 HTTPS를 통해 수행됨
- `fetch()` 기본 설정 사용 (credentials: same-origin 기본값)
- 인증 헤더 없음 -- API 키, Bearer 토큰 등의 민감 정보가 요청에 포함되지 않음
- API 에러 응답 처리: `data.error` 확인 후 예외 발생
- 요청 타임아웃 설정 없음, 속도 제한(rate limiting) 없음

### 5.2 Referrer 정책

`getImageUrl()` 함수에서 이미지 다운로드 URL 요청 시:

```javascript
const response = await fetch(getFileLink(code, fileid), {
    referrerPolicy: 'no-referrer'
});
```

- `no-referrer` 설정으로 pCloud API에 Referer 헤더를 전송하지 않음
- 호스팅 URL(GitHub Pages 주소) 노출 방지
- `<img src>` 태그에는 별도 `referrerpolicy` 속성 미설정 -- 브라우저 기본값 적용

### 5.3 이미지 로딩

- 이미지 URL은 pCloud API 응답에서 동적으로 생성: `` `https://${data.hosts[0]}${data.path}` ``
- `<img src={url}>` -- URL은 API 응답에서 가져오며, 사용자 입력을 직접 src로 사용하지 않음
- `loading="lazy"` 속성으로 지연 로딩 적용
- `Promise.all()`로 모든 이미지 URL을 동시 요청 -- 클라이언트 측 속도 제한 없음

### 5.4 CORS/CSP

- Content Security Policy(CSP) 헤더 및 meta 태그 미설정
- CORS는 pCloud API 서버 측에서 허용
- GitHub Pages 기본 보안 헤더에 의존
- GitHub Pages에서 커스텀 HTTP 응답 헤더 설정 불가

## 6. 배포 보안

### 6.1 GitHub Actions 워크플로 (`deploy.yml`)

**권한 설정:**

```yaml
permissions:
  contents: read    # 소스 코드 읽기 전용
  pages: write      # Pages 배포 권한
  id-token: write   # OIDC 토큰 (Pages 배포 인증)
```

- `contents: read`로 최소 권한 원칙 준수 -- 소스 코드 쓰기 불가
- `id-token: write`는 GitHub Pages 배포 시 OIDC 인증에 필요
- 트리거 제한: `main` 브랜치 push와 수동 실행(`workflow_dispatch`)으로만 배포 가능

**동시성 제어:**

```yaml
concurrency:
  group: 'pages'
  cancel-in-progress: false
```

- 동일 그룹 내 동시 배포 방지
- `cancel-in-progress: false`로 진행 중인 배포를 취소하지 않음

**빌드 프로세스:**
- `npm ci`로 lock 파일 기반 정확한 의존성 설치 (`npm install` 대신)
- `NODE_ENV: production`만 환경 변수로 전달
- 시크릿이나 API 키 주입 없음
- GitHub Actions 액션 버전이 태그 기반(`@v4`)이며 커밋 SHA로 고정되어 있지 않음

### 6.2 빌드 설정 (`svelte.config.js`)

```javascript
paths: {
    base: process.env.NODE_ENV === 'production' ? '/PclToon' : ''
}
```

- `NODE_ENV`만 참조하며, 런타임 시크릿 노출 경로 없음
- `adapter-static`으로 정적 파일만 생성 -- 서버 측 코드 실행 불가
- `ssr: false`, `prerender: true` -- 서버 측 렌더링 비활성화, 빌드 타임 HTML 생성
- `strict: true` -- 엄격 모드로 누락된 경로 감지
- `fallback: 'index.html'` -- SPA 라우팅 지원

### 6.3 소스 코드 보호 (`.gitignore`)

- `.env`, `.env.*` 패턴 제외 -- 환경 변수 파일 보호 (실제로 env 파일을 사용하지 않지만 예방적 설정)
- `!.env.example`, `!.env.test`는 허용 (민감 정보 미포함 전제)
- `node_modules/`, `/build`, `/.svelte-kit` 빌드 산출물 제외
- 시크릿이나 자격 증명이 소스 코드에 하드코딩되어 있지 않음

### 6.4 정적 호스팅 (GitHub Pages)

- HTTPS 강제 적용 (GitHub Pages 기본)
- DDoS 보호 (GitHub 인프라)
- TLS 인증서 자동 관리
- 커스텀 HTTP 응답 헤더 설정 불가 (`.htaccess` 또는 서버 설정 불가)
