# 10. Deploy Plan

## 1. 배포 개요

PclToon은 SvelteKit + `adapter-static` 기반 순수 클라이언트 사이드 SPA로, 정적 파일로 빌드되어 GitHub Pages에 호스팅된다. CI/CD는 GitHub Actions 워크플로우를 통해 자동화되어 있다.

| 항목 | 설정값 |
|------|--------|
| 애플리케이션 유형 | SvelteKit + adapter-static 기반 순수 클라이언트 사이드 SPA |
| 빌드 어댑터 | `@sveltejs/adapter-static` |
| 빌드 도구 | Vite (`@tailwindcss/vite` + `sveltekit()` 플러그인) |
| 호스팅 | GitHub Pages (정적 사이트) |
| CI/CD | GitHub Actions |
| Node.js | 20 LTS |
| 패키지 매니저 | npm (`npm ci`) |
| 컨테이너화 | 없음 (Docker 파일 미존재) |
| 런타임 환경 변수 | 없음 (빌드 시 `NODE_ENV`만 참조) |

## 2. 빌드 프로세스

### 2.1 npm scripts (`package.json`)

```json
{
  "dev": "vite dev",
  "build": "vite build",
  "preview": "vite preview",
  "prepare": "svelte-kit sync || echo ''"
}
```

- `npm run build` 실행 시 Vite가 SvelteKit 프로젝트를 빌드한다.
- `prepare` 스크립트는 `npm ci` 후 자동 실행되어 SvelteKit 타입 동기화를 수행한다. `|| echo ''`로 실패 시에도 설치 프로세스가 중단되지 않는다.

### 2.2 Vite 플러그인 (`vite.config.js`)

```javascript
import { sveltekit } from '@sveltejs/kit/vite';
import tailwindcss from '@tailwindcss/vite';
import { defineConfig } from 'vite';

export default defineConfig({
  plugins: [tailwindcss(), sveltekit()]
});
```

- `@tailwindcss/vite`: Tailwind CSS Vite 통합 플러그인
- `sveltekit()`: SvelteKit Vite 플러그인
- 별도의 커스텀 Vite 설정(프록시, 별칭, 환경 변수 정의 등)은 존재하지 않는다.

### 2.3 adapter-static 설정 (`svelte.config.js`)

```javascript
import adapter from '@sveltejs/adapter-static';

const config = {
  kit: {
    adapter: adapter({
      pages: 'build',
      assets: 'build',
      fallback: 'index.html',
      precompress: false,
      strict: true
    }),
    paths: {
      base: process.env.NODE_ENV === 'production' ? '/PclToon' : ''
    }
  }
};
export default config;
```

| 옵션 | 값 | 설명 |
|------|----|------|
| `pages` | `'build'` | HTML 출력 디렉토리 |
| `assets` | `'build'` | 정적 에셋 출력 디렉토리 |
| `fallback` | `'index.html'` | SPA 클라이언트 라우팅을 위한 폴백 페이지 |
| `precompress` | `false` | gzip/brotli 사전 압축 비활성화 (GitHub Pages CDN이 자체 압축 처리) |
| `strict` | `true` | 프리렌더링 검증 활성화 (fallback 설정 시 SPA 모드로 동작) |

- 출력 디렉토리: `build/` (pages와 assets 모두 동일 경로)
- SPA 폴백: `index.html`로 설정되어 모든 경로에서 클라이언트 사이드 라우팅 지원

### 2.4 `.npmrc`

```
engine-strict=true
```

- Node.js 엔진 버전 불일치 시 `npm install` 실패 처리

## 3. CI/CD 파이프라인

### 3.1 워크플로우 파일 (`.github/workflows/deploy.yml`)

#### 트리거

```yaml
on:
  push:
    branches: ['main']
  workflow_dispatch:
```

- `main` 브랜치에 push 시 자동 배포
- `workflow_dispatch`를 통한 GitHub UI 수동 실행 가능
- 별도의 PR 미리보기(preview deployment) 또는 스테이징 환경 배포는 구성되어 있지 않다.

#### 권한 설정

```yaml
permissions:
  contents: read
  pages: write
  id-token: write
```

| 권한 | 용도 |
|------|------|
| `contents: read` | 리포지토리 코드 체크아웃 (읽기 전용) |
| `pages: write` | GitHub Pages 배포 아티팩트 업로드 |
| `id-token: write` | OIDC 토큰 발급 (GitHub Pages 배포 인증) |

- OIDC 토큰 기반 인증을 사용하므로 별도의 시크릿(PAT 등)이 필요하지 않다.

#### 빌드 Job (`build`)

```yaml
build:
  runs-on: ubuntu-latest
  steps:
    - name: Checkout
      uses: actions/checkout@v4
    - name: Setup Node
      uses: actions/setup-node@v4
      with:
        node-version: '20'
        cache: 'npm'
    - name: Install dependencies
      run: npm ci
    - name: Build
      run: npm run build
      env:
        NODE_ENV: production
    - name: Upload artifact
      uses: actions/upload-pages-artifact@v3
      with:
        path: 'build'
```

| 단계 | Action/명령 | 설명 |
|------|------------|------|
| Checkout | `actions/checkout@v4` | 소스 코드 체크아웃 |
| Setup Node | `actions/setup-node@v4` | Node.js 20 설치, npm 캐시 활성화 |
| Install dependencies | `npm ci` | `package-lock.json` 기반 의존성 설치 (재현 가능한 빌드 보장) |
| Build | `npm run build` | `NODE_ENV=production` 환경에서 Vite 빌드 실행 |
| Upload artifact | `actions/upload-pages-artifact@v3` | `build/` 디렉토리를 Pages 아티팩트로 업로드 |

#### 배포 Job (`deploy`)

```yaml
deploy:
  environment:
    name: github-pages
    url: ${{ steps.deployment.outputs.page_url }}
  runs-on: ubuntu-latest
  needs: build
  steps:
    - name: Deploy to GitHub Pages
      id: deployment
      uses: actions/deploy-pages@v4
```

- `needs: build` --- 빌드 Job 완료 후 순차 실행
- `actions/deploy-pages@v4`가 빌드 아티팩트를 GitHub Pages에 배포
- `environment` 블록이 GitHub 저장소의 Environments 탭에 `github-pages` 환경을 등록
- 배포 완료 시 `page_url` output으로 배포된 URL 출력

## 4. 환경 설정

### 4.1 NODE_ENV에 따른 base path 분기

```javascript
paths: {
  base: process.env.NODE_ENV === 'production' ? '/PclToon' : ''
}
```

| 환경 | `NODE_ENV` | Base Path | 결과 URL |
|------|-----------|-----------|----------|
| 프로덕션 | `production` | `/PclToon` | `https://<user>.github.io/PclToon/` |
| 로컬 개발 | 미설정 (기본값) | `''` (빈 문자열) | `http://localhost:5173/` |

GitHub Pages는 저장소 이름을 하위 경로로 사용하므로(`/<repo-name>/`), 프로덕션 빌드에서 `/PclToon` base path가 필수적이다. 로컬 개발 시에는 루트 경로에서 동작한다.

### 4.2 환경 변수 요약

| 변수 | 값 | 사용 위치 | 용도 |
|------|------|-----------|------|
| `NODE_ENV` | `production` | GitHub Actions 빌드 단계 (`deploy.yml`) | base path 분기 결정 |

- 런타임 환경 변수는 존재하지 않는다 (정적 사이트이므로 불필요).
- `.env` 파일은 `.gitignore`에 포함되어 있으나, 실제 `.env` 파일은 프로젝트에 존재하지 않으며 필요하지도 않다.

## 5. 인프라 구성

### 5.1 GitHub Pages 설정

| 항목 | 설정 |
|------|------|
| 배포 방식 | GitHub Actions 워크플로우 아티팩트 기반 자동 배포 |
| 배포 소스 | 빌드 아티팩트 직접 배포 (저장소 브랜치 기반이 아님) |
| 환경 이름 | `github-pages` |
| HTTPS | GitHub Pages 기본 제공 (자동 인증서 발급/갱신) |
| CDN | GitHub 글로벌 CDN 인프라 (Fastly) |
| 커스텀 도메인 | 미설정 (기본 `github.io` 도메인 사용) |

별도의 CDN, 리버스 프록시, 로드 밸런서, 컨테이너 인프라는 구성되어 있지 않다.

### 5.2 동시성 제어

```yaml
concurrency:
  group: 'pages'
  cancel-in-progress: false
```

- `group: 'pages'` --- 동일 그룹의 워크플로우가 동시 실행되지 않도록 제어
- `cancel-in-progress: false` --- 진행 중인 배포를 취소하지 않음 (배포 안정성 우선)
- 동일 그룹의 후속 워크플로우는 이전 실행 완료까지 대기

### 5.3 SPA 라우팅 처리

- `fallback: 'index.html'` 설정으로 모든 경로가 `index.html`로 폴백
- GitHub Pages에서 존재하지 않는 경로 요청 시 `index.html`이 서빙되어 클라이언트 라우터가 처리

## 6. 로컬 개발 환경

| 명령어 | 실행 | 용도 |
|--------|------|------|
| `npm run dev` | `vite dev` | 개발 서버 실행 (HMR 지원, base path `''`) |
| `npm run build` | `vite build` | 프로덕션 빌드 |
| `npm run preview` | `vite preview` | 빌드 결과물 로컬 미리보기 서버 |
| `npm run prepare` | `svelte-kit sync \|\| echo ''` | SvelteKit 타입 동기화 |

- 개발 서버: `vite dev`는 HMR(Hot Module Replacement)을 지원하며, base path 없이 `http://localhost:5173/`에서 동작한다.
- 프로덕션 빌드 로컬 테스트: `NODE_ENV=production npm run build && npm run preview`
- `vite preview`는 `build/` 디렉토리의 빌드 결과물을 로컬에서 서빙한다.

## 7. 배포 URL 및 경로 체계

```
프로덕션: https://<user>.github.io/PclToon/
                                    └── base path: /PclToon
```

| 항목 | 값 |
|------|-----|
| 프로덕션 URL | `https://<user>.github.io/PclToon/` |
| Base Path | `/PclToon` (프로덕션) / `''` (로컬 개발) |
| 에셋 경로 | 빌드 시 `/PclToon/` 접두사 자동 적용 |
| 라우팅 | SPA 클라이언트 사이드 라우팅 (fallback: `index.html`) |

- 모든 에셋 경로는 프로덕션 빌드 시 `/PclToon/` 접두사가 적용된다.
- SvelteKit의 `$app/paths`에서 `base`를 import하여 런타임에 경로를 참조한다.
- SPA fallback으로 클라이언트 사이드 라우팅이 전체 지원된다.
